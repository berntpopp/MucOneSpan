# MucOneSpan v0.16.1 ladder bug-fix release: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.16.1 of the default ladder engine with three small, targeted, ladder-only fixes:

- **Fix A (safety).** Stop reporting NEGATIVE when Clair3's pileup stage saw a frameshift indel that the applied call set dropped.
  - On the diag12d `ms_ont_sub` set (older simulated ONT reads, R9 Clair3 model), v0.16.0 calls 12/39 pathogenic samples NEGATIVE. Fix A turns 11 of them into INCONCLUSIVE.
  - Measured by replaying the fix over every existing benchmark and cohort output (see Evidence E1). No other decision changes in any set, and no normal control changes.
- **Fix B (owner directive).** The clinical-decision thresholds hardcoded in `report.py` become settings: `ambiguous_bases > 10` and `LEGACY_MIN_TOTAL_READS = 30`. Default behaviour stays identical.
- **Fix C (owner directive).** The literal thresholds on the executed ladder allele-selection path become settings. Default behaviour stays identical. As a side effect, a hardcoded `- 9` fixed-repeat count is replaced by `reference_layout.fixed_repeat_count`, which fixes custom reference layouts.

CLI flags and output schemas are kept; output schemas only gain fields.

**Architecture:**

- Fix A adds one module, `stage_concordance.py`, called from the three places in `calling.py` that already hold a raw Clair3 VCF, the filtered VCF and the contig reference. It records `alleles[*].stage_concordance`.
- A new reason function in the same module adds a NEGATIVE-blocking reason. The reason is appended to the existing `selection_reasons` list in `report.compute_clinical_decision`.
- The gate can only turn NEGATIVE into INCONCLUSIVE, or add a caveat to PATHOGENIC. It never creates or removes a call.
- Fix B adds a `clinical_decision` settings section and a small resolver, `decision_settings.py`. It reads thresholds in this order: explicit argument, then the configuration recorded in `summary.json`, then defaults. Re-scoring an old summary therefore stays reproducible.
- Fix C first moves the pure cluster helpers out of `alleles.py`, which is at 641 lines. It then routes every literal through `AlleleSelectionSettings` / `ReadPhasingSettings`.

**Tech Stack:** Python 3.10+, Click, pytest (unittest.mock at the tool boundary), bcftools (`norm`, `query`), the existing `tools.run_tool` abstraction.

## 1. Triage of the candidate fixes

### New evidence gathered for this triage (v0.16.0 outputs, read-only replay)

- **E1: ONT single-base-insertion false negatives (why the NEGATIVE gates pass).** In `diag12d/runs/ms_ont_sub/v0.16.0` (78 samples: 39 pathogenic, 39 normal; model `models/ont`, R9), 12 pathogenic samples are NEGATIVE. The events are insG_pos54 ×3, insG ×2, insA_pos54 ×2, delGCCCA ×2, dupC, insC_pos23 and insG_pos58. Every allele passes QC: lengths are correct, selection is `resolved`, `depth_status=adequate` (121–364 primary records), `allele_specific_resolved`, no heterozygous sites, 0 ambiguous bases.
  - In 10/12, Clair3's **pileup** stage (`clair3/pileup.vcf.gz`) calls the event as a frameshift indel at FORMAT/AF 0.68–0.85 (DP 33–408). The full-alignment stage makes no call, so `merge_output.vcf.gz` lacks it. Example: pair_5152, `contig_82:2833 C>CG`, AF 0.719, DP 121.
  - In 1/12 (pair_5147), full-alignment reports it with QUAL 0 (AF 0.72, DP 107), so the `QUAL>=4` filter removes it.
  - In 1/12 (pair_5178, delGCCCA), no Clair3 stage emits it (pileup maximum AF 0.03). This is a true caller miss.
  - The pipeline reads only `merge_output.vcf.gz`, then the filtered `variants.vcf.gz`. The consensus therefore stays reference at the site, the classifier finds nothing, and there is no event to gate.
  - **Why the NEGATIVE gates pass:** every NEGATIVE requirement is structural (execution, selection, length, per-allele depth, genotype of *called* records, IUPAC count, reconstruction) or concerns called events. No gate asks whether the caller discarded read evidence for a frameshift, so "no event called" is treated as "no event present".
  - Model and read type do not explain it by themselves. The allele-QC fields do not separate the 12 FN from the 25 true negatives: the fraction of fuzzy (`?`) units is 0.00–0.26 in both groups.
- **E2: separation of the proposed veto.** The veto flags a frameshift indel (length change not divisible by 3) that meets three conditions: it is in the pileup VCF, it is not applied by any genotype in the filtered VCF of the same partition, and it has FORMAT/AF ≥ 0.5 and DP ≥ 10.
  - Replayed over every v0.16.0 output set (cohort-p0, v3/standard, v3/clean, v3/clean2, v2/stress, and diag12d ms_ont_sub, ms_pacbio_sub, oldtest, leg_ont, leg_hifi, leg200_ont, leg200_hifi).
  - Of 96 NEGATIVE decisions, **11 are flagged, all pathogenic truths in ms_ont_sub**. The highest AF among unflagged NEGATIVE cases is 0.156 (a normal).
  - **Zero** decisions change in any other set, including cohort-p0, where HG001/HG003 stay NEGATIVE.
  - Any depth floor from 3 to 33 gives identical results. Without a floor, one normal (v3/clean ONT 0028) is flagged by a flank-end insertion at DP 2.
  - FORMAT/AD is unusable for pileup records: AD is sparse (for example `AD 6,6` at DP 98). An AD-fraction rule would flag about 4 normal controls. FORMAT/AF (alt reads / DP) is the right measure here.
- **E3: how many decisions a single-gate fix can move.** INCONCLUSIVE cases whose reasons fall in exactly one reason class:
  - v3/standard: 0/86;
  - v3/clean: 5/81 (depth 1, event 1, reconstruction 1, selection 1, plus 1 depth-only);
  - v3/clean2: 1/21 (event);
  - v2/stress: 9/81, 5 of them depth-only, all expected at low design depth.
  - In no dev set can any single ladder gate fix change more than about 1 decision.
- **E4: read-level support for templated events.** Named events whose *only* blocker is "no explicit sequence-level support":
  - v3/standard: 2 (ins16bp HiFi 0014, ins16bp genomic 0007);
  - v3/clean: 3 (delinsAT HiFi 0012, ins16bp HiFi 0014, ins25bp HiFi 0022);
  - v3/clean2: 1 (ins16bp ONT 0013, a true positive: design ins16bp at unit 29 of the 58-unit allele).
  - `vcf_support_status` is `absent` or `projection_unavailable`. Every other named event also carries `localization ambiguous`, which read support does not lift.
- **E5: genomic length doubling.** ONT genomic, allele_1's cluster runs from `contig_1` over more than 50 contigs in 23/30 (standard) and 26/30 (clean) cases. The called length exceeds the longest truth allele by more than 20 units in 25/30 and 29/30.
  - Mechanism: non-spanning genomic fragments align to every ladder contig at least as long as their VNTR portion, so the "cluster" is the whole ladder. The weighted centre and refinement then land high (for example 142/146 for 77/77).
  - Clinical outcome: 0 FP, and no NEGATIVE on a pathogenic genomic case in either set (standard genomic 30/30 INCONCLUSIVE).
- **E6: decision hardcodes.** On all dev sets, no decision depends on `ambiguous_bases > 10` alone (0 single-reason cases). Moving it into a setting is behaviour-neutral.

**Issue A**

Title: `fix(calling): NEGATIVE despite a frameshift that Clair3's pileup stage called and the final call set dropped (11/39 simulated ONT pathogenic samples)`

Body:
```markdown
## Summary
On older simulated ONT amplicon reads called with the R9 Clair3 model, v0.16.0 reports
NO_PATHOGENIC_VARIANT_DETECTED for 12/39 pathogenic samples (benchmark set diag12d
`ms_ont_sub`, 78 samples). The allele QC passes in all 12: correct lengths, resolved
selection, adequate per-allele depth (121–364 primary records), allele-specific genotype,
no heterozygous sites, 0 ambiguous bases.

## Mechanism
- 10/12: Clair3's pileup stage (`clair3/pileup.vcf.gz`) calls the event as a frameshift
  indel at FORMAT/AF 0.68–0.85 (DP 33–408), for example `contig_82:2833 C>CG`, AF 0.719,
  DP 121. The full-alignment stage makes no call, so `merge_output.vcf.gz` lacks it.
- 1/12: full-alignment reports it with QUAL 0. The `QUAL>=4` filter removes it.
- 1/12 (delGCCCA): no Clair3 stage emits it (residual; needs read-level evidence).

The pipeline reads only `merge_output.vcf.gz`. The consensus stays reference at the site and
the classifier finds nothing.

## Why the NEGATIVE gates pass
Every NEGATIVE requirement is structural (execution, allele selection, length, per-allele
depth, genotype of *called* records, ambiguous-base count, reconstruction) or concerns
called events. None asks whether the caller discarded read evidence for a frameshift. An
event that was not called is treated as an absent event.

## Proposed fix (ladder only, veto only)
Per length partition, compare the Clair3 pileup VCF (normalised with `bcftools norm -m -any`)
with the alleles actually applied by genotypes in the filtered VCF. A frameshift indel with
pileup FORMAT/AF >= `calling.stage_discordance_min_af` (0.5) and FORMAT/DP >=
`calling.stage_discordance_min_depth` (10) that is not applied is recorded as
`alleles[*].stage_concordance.status = "discordant_frameshift"`. It blocks NEGATIVE
(INCONCLUSIVE with a reason). With a PATHOGENIC call it is a quality caveat. It never creates
or removes a call.

## Measured effect (replay over existing v0.16.0 outputs)
- ms_ont_sub: NEGATIVE on pathogenic 12/39 → 1/39. NEGATIVE on normals 25/39 unchanged.
- 0 decision changes in PRJEB92208 cohort-p0, v3/standard, v3/clean, v3/clean2, v2, and the
  other diag12d sets (96 NEGATIVE decisions; the highest unflagged pileup AF is 0.156).

## Acceptance
- The ms_ont_sub rerun gives NEGATIVE on pathogenic <= 1/39, NEGATIVE on normals 25/39 and
  FP 0/39.
- No decision change in any other benchmark set or in PRJEB92208 (MP1, MP2, MP4 PATHOGENIC;
  HG001, HG003 NEGATIVE).
- The settings are documented. The output field is additive.
```

```python
def truth(name, root, run):
    if name == "cohort":
        return COHORT[run.name[-2:]]
    case = root.parents[2] / "dev" / run.name / "case.json"
    if case.is_file():
        return "pathogenic" if json.loads(case.read_text())["design"].get("event") else "normal"
    rows = {json.loads(l)["sample"]: json.loads(l) for l in (root / "scored.jsonl").open()}
    return rows[run.name]["truth"]

def partitions(run):
    merged = run / "merged"
    if merged.is_dir():
        phased = [(k, merged / k) for k in ("allele_1", "allele_2") if (merged / k / "variants.vcf.gz").is_file()]
        return [(k, d, merged) for k, d in phased] or [("allele_1", merged, merged)]
    return [(k, run / k, run / k) for k in ("allele_1", "allele_2") if (run / k / "variants.vcf.gz").is_file()]

def main():
    p = argparse.ArgumentParser(); p.add_argument("--out", type=Path, required=True)
    p.add_argument("--baseline-only", action="store_true"); a = p.parse_args()
    result = {}
    for name, root in SETS.items():
        rows = []
        for sj in sorted(root.glob("*/summary.json")):
            run, summary = sj.parent, json.loads(sj.read_text())
            before = compute_clinical_decision(summary)["state"]
            after = before
            if not a.baseline_only:
                from muc_one_span.stage_concordance import annotate_stage_concordance
                from muc_one_span.settings import DEFAULT_SETTINGS
                with tempfile.TemporaryDirectory() as tmp:
                    for key, part, refdir in partitions(run):
                        contig = summary["alleles"][key]["contig_name"]
                        summary["alleles"][key]["stage_concordance"] = annotate_stage_concordance(
                            part / "clair3" / "pileup.vcf.gz", part / "variants.vcf.gz",
                            refdir / f"{contig}.fa", DEFAULT_SETTINGS.calling, work_dir=Path(tmp))
                after = compute_clinical_decision(summary)["state"]
            rows.append({"run": run.name, "truth": truth(name, root, run), "before": before, "after": after})
        result[name] = {"counts": Counter(r["after"] for r in rows),
                        "transitions": Counter(f'{r["truth"]}:{r["before"]}->{r["after"]}' for r in rows if r["before"] != r["after"]),
                        "changed": [r for r in rows if r["before"] != r["after"]]}
        print(name, dict(result[name]["counts"]), dict(result[name]["transitions"]))
    a.out.write_text(json.dumps(result, indent=1, default=dict) + "\n")

main()
```
