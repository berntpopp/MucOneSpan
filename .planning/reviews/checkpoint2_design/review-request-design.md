## Review Request Overview

We request an exceptionally rigorous, critical review of the proposed architectural design for improving `MucOneSpan`. The proposed changes are designed to resolve systematic failure modes on a benchmark panel of 200 newly simulated datasets (140 dev, 60 final validation) generated by `MucOneUp`.

Please review `.planning/2026-09-14-architectural-design.md` and address the following technical questions:

### 1. Family A (Proximal Flank Reference & Trimming Alignment)
- In v0.11.0, `ladder.py` sliced `flanking_left[:flank_length]`, taking the distal 500 bp from a 10 kb upstream sequence. The proposal switches to `flanking_left[-flank_length:]` (proximal 500 bp adjacent to pre-repeat unit 1).
- Does this change introduce any hidden side-effects in minimap2 alignment, coordinate arithmetic, or downstream `trim_flanking`?
- What anchor tolerance and boundary validation should be enforced to prevent over-trimming or under-trimming?

### 2. Family C (Read-Dominance Length Inference & Molecule Partitioning)
- The proposal replaces 1D contig count clustering and indel-valley slicing (`_split_cluster_by_indel`) with a per-read alignment score (AS) dominance margin test:
  $$\Delta AS(r_k) = AS(r_k, c_{(2)}) - AS(r_k, c_{(1)}) > \delta_{\text{margin}}$$
  requiring $\ge m_{\min}$ reads and $\ge 75\%$ positive margin to accept a second candidate length.
- Does this formulation cleanly eliminate false splitting of identical 60/60 homozygous controls while preserving extreme asymmetric minority alleles (25/140 at 5% coverage)?
- How should $\delta_{\text{margin}}$ and $m_{\min}$ differ between PacBio HiFi (high base accuracy, sharp AS peaks) and ONT (higher indel noise, broader AS distributions)?
- What fallback behavior should occur when read support is ambiguous or near the margin?

### 3. Family D (Haploid Calling & Diploid Phasing Invariants)
- For separated alleles, the proposal runs Clair3 in haploid mode (`--haploid_precise` / `--haploid_sensitive`) on partitioned read subsets.
- If a few reads from allele 2 cross-map to allele 1's contig (e.g. in close-length cases like gap 1 or gap 2), could haploid calling erroneously force a true heterozygous difference into an erroneous homozygous call or vice versa?
- For true same-length alleles, the proposal requires all heterozygous variants to belong to a single contiguous WhatsHap phase set, refusing to stitch disjoint blocks. Is this strictly safe against false-positive recombinant calls?

### 4. Implementation Constraints & Engineering Risks
- The repository enforces strict constraints: physical line count $\le 649$ lines per authored file, and $\ge 80\%$ branch-aware test coverage (`make ci-check`).
- What file structure or modular breakdown do you recommend to maintain high cohesion without violating the 649 line limit?
- What specific unit tests must be added to guarantee zero regression on previously passing baseline cases?

Please provide a critical, constructive evaluation with concrete suggestions, mathematical adjustments, or alternative designs where appropriate.
